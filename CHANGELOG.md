## 0.18.0 — architect experience, the workbench and the improvement roadmap (2026-11-10)

Upgrade: change the pin to `@v0.18.0`, `pip install -r requirements.txt`, `sdem agents install`; regenerate your pages (`sdem build`, `view`, `dashboard`, `home`) to get the new navigation. Then move each workspace to metamodel 0.8.1: `sdem migrate --workspace <dir> --person <you> --dry-run`, then without `--dry-run` (additive; in a workspace with change sets the migration is recorded as one). Two behaviours changed: `sdem check` reads a placeholder (`TBD`, `unknown`, `/TBD`) or an empty string in a required attribute as missing, and a change-set `update` merges unless it says `"replace": true`. Other commands work as before.

- **An organisation's own standards, reference-architecture patterns and exceptions (PR-13…PR-20; the owner's decisions B1–B6).** A profile now `includes` standards files (security, network, technology …) and pattern files, each with its own id, version, owner and effective date, kept in the organisation's private repository. Rules can compare values (`check`: `in`, `<=`, `after today+180d` …), follow **approved** links across layers (`across`: e.g. a tier 1 application's platform is in the restricted zone), and be warnings rather than errors. A pattern (e.g. *Secure API integration*) lists what a design must have where it applies, across layers. **`sdem comply`** reports every rule and record — compliant, not met, unresolved (unknown, inferred or planned: never counted compliant), or under an exception — separately from `sdem check`; **`sdem exception grant`** records a person's time-limited exception (a governed decision; an agent is refused), and the finding returns when it expires. Two gaps closed: a placeholder (`TBD`) no longer satisfies a profile rule, and a team profile can no longer widen or redeclare its base's lists or reuse a base rule id (narrowing is explicit, `narrows`). A profile can no longer redefine one of **SDEM's own attributes** either (it was accepted, and replaced SDEM's definition) — so an attribute a later SDEM adds that a profile already declares is reported by `sdem upgrade check` before the switch; rename yours (e.g. `bank_end_of_support`). `sdem handback` lists unmet standards and exceptions ending within 30 days. Synthetic examples: `examples/profiles/bank-with-standards.json` and its standards and pattern.
- **Word, Excel and single-file designs in `sdem transform` (HI-F01…HI-F03).** `sdem transform run ledger-design.xlsx -o work/history` reads an Excel workbook tab by tab: each tab is a section named after it, each table on it is read by the same rules as a Confluence table, and each record cites its sheet row. Names are gathered across all tabs, so an *Interfaces* tab (Source, Target) links applications listed on an *Applications* tab, and a new rule **HL-02** (approved by the owner, 2026-11-11) reads a *Deployment* tab (Application, Runs on) as candidate deployments. Title lines, merged cells and formulas (as Excel last saved them) are handled; hidden tabs and tabs no rule reads are reported, never guessed. Word (`.docx`) files are read like Markdown — headings, tables and paragraphs; pictures inside them are reported for a person. A single file, or design files in the export's top folder, are now read as designs; an older `.doc`/`.xls`, PDF or PowerPoint is reported with what to save it as. Standard library only; free text still makes no records without an AI agent.
- **An organisation above its workspaces (WS-08…WS-10).** `sdem new --organisation bank-xyz --person you` starts the organisation's folder with a starter base profile (`profiles/bank-xyz-base.json`, its design specification) and `workspaces/`. `sdem new --workspace workspaces/ledger --organisation bank-xyz --person you` then starts a workspace inside it whose own profile extends the base, so the organisation's types, attributes and rules apply from the start; inside the organisation's folder it is found without `--organisation`. A workspace outside the organisation, or an organisation that does not exist, is refused; `--profile FILE` still wins. A workspace on its own works as before. README step 2 now starts with the organisation.
- **Reference patterns as structures, from the organisation's own diagrams (PR-21…PR-31; the owner's decisions S1–S6).** A pattern can now say what its parts are (roles, each a type), how they connect (each a link the metamodel already allows: `sdem profile check` refuses any other) and which zone each sits in. SDEM finds the records that fill each part, starting from each record that follows the pattern; a record can name its part in SDEM's own `conforms_to` (`PAT-ID#part`), and two candidates for one part are reported, never guessed. `sdem comply` and `sdem check` report a part that is missing, in the wrong zone, or not met; an exception can name one part. **`sdem pattern extract`** reads a pattern drawn in **draw.io, Visio, PlantUML or Mermaid** (standard library only) into a draft pattern file, using the profile's new `diagram_map` (the organisation's shape names, connector labels and zones). Every part cites its shape; anything not mapped, not allowed or not read is listed. The pattern owner reviews and includes the draft, and `--compare` shows what changed when the diagram changes. **`sdem pattern draw`** draws the pattern, or the design over it with each part marked. Made-up samples: `examples/profiles/patterns/diagrams/secure-api-edge.{drawio,vsdx,puml,mmd}` — one pattern, four formats, the same result. The metamodel is unchanged.
- **A full bank simulation** (`tests/test_bank_simulation.py`, synthetic): a made-up bank's design specifications in all four layers (key decisions, risks, deviations, scope, adoption scope), its security, network, technology and design standards, and two reference patterns, over a design in A1–A4. It checks the design **upstream** (a platform serving no approved application; an application whose BIAN domain the bank does not adopt; a domain supporting a capability outside the scope; only approved links count), **downstream** (trace and impact reach every layer, the same with and without the profile) and **sidestream** (the standards and patterns, a placeholder decision, a deviation held by an exception until it ends). It also proves the metamodel is unchanged: every SDEM type, link and attribute stays as it is, and the bank's are added beside them. A record's pattern reference is SDEM's own `conforms_to`: a rule's `when` now matches a list attribute that contains the value (PR-10), so a pattern applies to the records that say they follow it. Patterns as structures followed from it (next entry; [design](docs/design/sdem-structural-patterns-design.md)).

- **Improvement roadmap #1–#6, from the owner's independent assessment (decisions D1–D7, 2026-11-09).** Metamodel **0.8.1** (additive — 0.9.0 stays the release that removes the link type deprecated in 0.8.0; `sdem migrate` moves a workspace):
  - **A placeholder is not a value (#1, LC-04).** `sdem check` now reads `TBD`, `unknown`, `?`, a path such as `/TBD`, or an empty string in a required attribute as *missing* — an error on an active record, a warning on a planned one, a warning in an optional attribute. Before, they passed every check. An empty list still means "none". The skills no longer tell agents to write `TBD`: a value nobody knows is left out on a `planned` record.
  - **Natural keys work for operations (#6, LC-09).** The duplicate check never ran for API operations, BIAN service operations and control records — their key includes the interface or service domain they belong to, which is a link, not an attribute. It now follows the link. Names that differ only in case, spacing or punctuation are reported as a **possible duplicate** (LC-09n).
  - **Where each value and link came from (#3).** A within-layer link may carry `source_id`; a record may carry `sources` — attribute → `kind:ref` (new common attribute CA-13, checked by LC-14). `sdem document`, the workbench and `sdem transform` (which now keeps each link's Confluence pages) show them.

Weakness is read from the class, not from words in the reasoning (a structural fallback was wrongly capped at low before); AID-M03 now works both ways by class; agreement between the sides no longer lifts a link that rests on a name alone. `sdem model calibrate` reports observed precision per band and class — 100 % everywhere on the eight acceptance cases, which says the golds were written with the rules known, not that the bands are calibrated.
  - **`sdem change diff` and merging updates (#4, AG-K08, AG-K09).** An `update` in a change set now changes only what it gives (an attribute given as `null` is removed; `"replace": true` for the old behaviour) — a partial record no longer silently drops attributes. `sdem change diff` compares records drafted as a layer file with the workspace and writes the change set: adds, updates (only what differs), conflicts and possible duplicates; a record the file leaves out is never removed — with `--complete` it is a retirement candidate for a person. A change set may now change links only.
  - **`sdem handback` (#5, AG-H01…H03).** What a workspace leaves for a person — failing checks, values nobody knows, unconfirmed inferences with their evidence class, links to review, possible duplicates, unsourced records and links, events to plan — read from the workspace, with the commands to run. The skills and `AGENTS.md` (rules 8 and 11) end every task with it.

## 0.17.0 — update SDEM without harming your work (2026-11-03)

Upgrade: change the pin to `@v0.17.0`, `pip install -r requirements.txt`, `sdem agents install`. No metamodel change, no migration. From now on, before each upgrade, run the new version's `sdem upgrade check` first.

- **[Updating SDEM safely](docs/design/sdem-update-framework.md)** (UF-01…UF-08). SDEM is a product you install; your work and your customisations live in your own repository and never leave it. An update replaces SDEM and never changes your data unless you run a recorded migration.
- **`sdem upgrade check`** — run by the *new* version, installed side by side, against your workspaces; writes nothing. Per workspace: the migration needed and what it changes in the data (checked as a dry run), whether your profile passes, connections using a deprecated link type, check errors; for the repository: the agent files that would be updated and those your team changed (kept); a verdict — ready, migrate or blocked — and the steps in order.
- **`sdem releases --since <version>`** — release notes as data (`sdem/releases.json`, in the package): per release, its kind, metamodel version, migration, breaking changes, deprecations and the actions to take.
- **Profiles state the SDEM they need**: `requires_sdem` (e.g. `">=0.13,<1.0"`); a version outside it refuses the profile, saying so.
- **The version promise**, enforced by tests: a patch never changes your data or the metamodel; a minor may change the metamodel, always with a recorded, checked migration, and removes nothing not deprecated first.
- The administration guide and the workspace-repository template now start every upgrade with the side-by-side check; skipping releases is allowed (migrations chain) — read the actions in between.

## 0.7.0 — renamed SDEM, the Service Domain Enterprise Metamodel

- **Name.** SDMM → **SDEM (Service Domain Enterprise Metamodel)**, positioned as a model-driven enterprise architecture metamodel. Principles, A1–A4 levels, behaviour and data are unchanged.

## 0.3.1

Level naming: the four design models are now the **Service Domain Architecture Design Model (SDADM)** — A1 Business Architecture, A2 Service Domain Architecture, A3 Application Architecture, A4 Technology Architecture. The `L0.`–`L3.` prefixes were an institution's own numbering, not a generic one.

- Entity types are prefixed `A1.`–`A4.`; the registry declares an ordered `levels` list, `bian_level`, and `type_aliases` mapping `L0.`–`L3.` to `A1.`–`A4.`.
- Older documents validate unchanged through the aliases; `sdmm-diff` treats an aliased prefix rename as no change, so approved records can be migrated without violating immutability.
- Registry version 0.3.0 (documents pinning `registry_version` bump the pin; that field is outside the frozen record).
- Adjacency and the BIAN-level `canonical_id` rule are driven by the registry's level list rather than a hard-coded digit.
- Docs renamed: `docs/history/01-a1-a2-mapping.md`, `02-a2-a3-mapping.md`, `03-a3-a4-mapping.md`.

## 0.3.0

- New `sdmm-trace` command: walk approved mappings downstream (what an entity depends on) or upstream (what depends on it), as a tree or JSON with every hop carrying its `mapping_id`. Superseded and proposed records are excluded unless `--status` includes them. Pure Python, no dependencies.
- Docs: v0.4 entity metamodel specification and roadmap track.

## 0.2.1

Validator hardening, in response to external review.

- `approved`, `rejected` and `superseded` records now require `approved_at` as well as `reviewer_id`.
- Mappings whose type has `bian_*` authority must carry `canonical_id` on their L1 endpoint. An unanchored BIAN-guided mapping no longer passes.
- Evidence may be cited as `kind:reference`; when it is, every kind in the registry's `required_evidence` must be present. Untyped evidence warns (`--strict` makes it an error).
- `EntityResolver` protocol and `CatalogueEntityResolver` (file-backed) let CI confirm every endpoint exists in a level model (`--catalogue`).
- New `sdmm-diff` command: lifecycle transitions and immutability of reviewed records, against a file or a git revision. Wired into CI against `HEAD~1`.
- Examples use typed evidence; `card-fraud-alerts` ships an `entities.json` catalogue.
- Docs: permitted transitions, immutability, evidence typing, authoritative vs derived relationships; roadmap reordered (graph before AI).
