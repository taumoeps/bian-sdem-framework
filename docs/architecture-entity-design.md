# SDEM Architecture Entity Design

Generated by `python -m sdem.catalogue` from the entity catalogue (`metamodel/a1…a4-*.json`); the test suite checks it is current. Part of the **Architecture Metamodel**: this document defines *which kinds of thing exist* in each of the four architectures, where each one comes from, why it is defined as it is, and how confident that basis is. The links allowed between them are in [`relationships-planning.md`](relationships-planning.md); the overview is [`sdem-overview.md`](sdem-overview.md).

## 1. Design principles

1. **Every entity type comes from a public reference architecture, or says that it does not.** No entity is named after, defined by or copied from an institution's model (README › *Reference architecture provenance*).
2. **One concept, one entity.** Where a standard defines the concept exactly, SDEM uses it unchanged and names the standard and chapter.
3. **Extensions are explicit.** Where SDEM needs something no standard defines, the entity is marked as an SDEM extension, names the standard concept it builds on, and records why.
4. **Artefacts are documents, not things.** BIAN's Business Object Model, wireframes and Semantic APIs are citable as evidence but never instantiated or used as a relationship end.
5. **Abstract types exist only for typing.** `A4.InfrastructureComponent` lets a relationship type target "any infrastructure"; it is never instantiated.

## 2. How source, verification and confidence are recorded

| Field | Meaning |
|---|---|
| Source reference | standard, release, concept, locator (chapter or page) and link, from the entity record |
| Source type | how the entity relates to the standard: native or reference (exact), aligned (interpreted), informed (TOGAF, gated), or SDEM extension; with the alignment kind |
| Verification | what has been checked: BIAN concepts against the public portal (**a licensed release is still pending**); ArchiMate concepts against the open-source Archi implementation of the relationship tables, because the specification text is login-gated; SDEM extensions are proposals |
| Reasoning | why the entity is defined this way and how its source supports it |
| **Confidence** | strength of the source basis — **high**: the concept exists one-to-one in a public standard; **medium**: interpreted from, or an SDEM extension of, a standard concept; **low**: SDEM design with no standard concept |

## 9. Review points

- **`A1.BusinessCapability` is rated high** because ArchiMate defines Capability exactly, although the record cites BIAN's Business Capability Model as its primary source with a *conceptual* alignment. Rated on the BIAN source alone it would be medium.
- **All 13 BIAN reference entities await validation against a licensed BIAN release**; their concepts are checked only against the public portal.
- **The ArchiMate entities are confirmed as concepts, not as specification text.** Reading the ArchiMate 3.2 specification (free Open Group account) would upgrade their verification; it would not change their confidence.
- **`A3.SolutionBuildingBlock` rests on TOGAF**, which is login-gated; its definition is SDEM's paraphrase.
