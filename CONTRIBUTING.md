# Contributing — the maintainer's guide

Please open an issue first for changes to entity types or link semantics. A pull request explains its purpose, the source and target types, cardinality, provenance, the expected lifecycle effect, examples and regression tests. **Never submit any organisation's confidential artefacts** (this repository is public and holds made-up data only) or third-party reference models without redistribution rights. The one third-party model included is the base BIAN in `bian/` (BIAN's public Semantic APIs, Apache-2.0) — change it only with `scripts/build_bian_base.py`, keeping `bian/LICENSE` and `bian/README.md` current. Contributions must be independently owned and offered under the repository's licenses; a contributor agreement or DCO policy can be added before community contributions begin.

## Set up

- Python **3.10 or later** (CI tests 3.10–3.13). No other dependencies.
- `pip install -e .` installs the `sdem` command; without installing, `python -m sdem …` does the same.
- Open the project in VS Code; run SDEM in the terminal pane ([user guide](docs/sdem-workbench-user-guide.md)).

## Before every pull request

```bash
python -m unittest discover -s tests          # the test suite (under 10 seconds)
python -m sdem model check                     # every generated document and schema is current
python -m sdem model accept                    # the rules engine passes its acceptance cases (8 of 8)
python scripts/engine_perf.py 30 30            # the rules engine on 2,040 records within 30 s
```
When you change `sdem/bian.py`, or BIAN publishes a release, also run `python scripts/bian_import_check.py <BIAN release folder>` against every file of a real downloaded release (not kept here).
CI (`.github/workflows/validate.yml`) runs these and more on every push, on Python 3.10–3.13, plus a job that builds the wheel, installs it in a clean environment and runs every journey from outside the repository.

## Generated files — never edit them by hand

Many documents and schemas are generated from the records in `metamodel/` and `schema/`. Edit the **source** — the JSON record or the generator in `sdem/` — then:

```bash
python -m sdem model regenerate                # rewrite every generated document, diagram and schema
python -m sdem model check                     # what CI checks
```

## Documentation rules — checked on every push

- **Every document in `docs/` says what it is** in a line under its title: `> **Status: …**` — current, approved, proposed, built, or a record — or *Generated by …* for generated ones (`tests/test_docs_operational.py`).
- **Every link resolves**, to a file and, after `#`, to a heading in it (same test). Rename a heading → fix the links to it.
- **No out-of-date wording** (`scripts/doc_drift.py`, run by `tests/test_doc_drift.py`): old command names, *draft* statuses, hard-coded test counts, old release status. Write `drift-ok` on a line that mentions an old name on purpose.
- **Where a document goes.** The top of `docs/` is only for people who use or run SDEM — plain words, no internal codes, nothing that needs a spec to finish a task (a test lists the files allowed there). Designs and specs go in `docs/design/`, generated reference in `docs/reference/`, test records in `docs/evidence/`, documents no longer current in `docs/history/`. A new document goes in the index of its folder ([`docs/README.md`](docs/README.md) or the folder's `README.md`).
- **Generated documents link by name** — write links as if from `docs/`; `sdem/docmap.py` rewrites them for wherever the document and its targets live.
- **Document changes need the owner's review** (`.github/CODEOWNERS`).

## Rules that must not be broken

- **The high-level spec is frozen.** `docs/design/architecture-metamodel-high-level-spec.md` is the owner's reference, pinned by a SHA-256 test. Changes go through the detail-level spec, and only with the owner's approval; gaps are called out first.
- **Controls stay controls.** A rule enforced in code (CTL-01…24, the round cap) is never weakened to an instruction. A new rule that matters gets a control and a test (good data accepted, bad data rejected) and a row in `metamodel/controls.json`.
- **Rules, not AI, inside SDEM.** No AI API client, no MCP server, no API key (`tests/test_copilot_setup.py` checks it). Copilot is optional and outside SDEM.
- **Source, reasoning and confidence** on every entity type, attribute, rule and decision — high only when the public source was checked.
- **Use-case examples are evidence.** After a change to the engine, the transform or the controls, re-run them (`python -m sdem model examples`; `python scripts/use_case_example_3.py`) and commit the updated evidence with the change.

## Releases

Releases are tagged by the owner. Before a tag: the CHANGELOG's *Unreleased* section moves under the version, `pyproject.toml`'s version and the pin in `templates/estate-repo/requirements.txt` are set to match (a test checks they agree), and the checks above pass. See [`docs/design/ROADMAP.md`](docs/design/ROADMAP.md).

## Where things are

The documentation is indexed by reader in [`docs/README.md`](docs/README.md); the code in `sdem/` (one module per journey, plus the generators), the rulebook in `metamodel/` and `schema/`, the made-up estates in `examples/`, scripts for examples and checks in `scripts/`, the Copilot agents, prompts and skills in `.github/`.
