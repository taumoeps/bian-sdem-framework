# A3 Application Architecture — Data Model (DRAFT for review)

> **Status: APPROVED 2026-10-25. Written into metamodel/entity-attributes.json (AT-A3-20…AT-A3-38).** Record: `metamodel/drafts/a3-descriptive-attributes.json`. Rendered by `python scripts/render_data_model_draft.py a3`.

**How to read each entity.** The **Data Model** table is the complete record for the entity: every field, its type, whether it is required, its allowed values, what it holds and its **source reference**. Fields come in groups — **Core** (identity, on every entity), **Common** (descriptive, on every entity), **Inherited** (from a parent entity) and **Specific** (this entity only). Each entity and each field carries its **source reference**, **reasoning** (for proposed fields, starting with the design question it answers) and **confidence**. In an architecture dataset file the common and specific fields sit inside the instance's `attributes` object.

**How the draft was built.** One field per design question, each from the highest available source — BIAN → open public standards readable without login (Dublin Core, W3C ORG, W3C SKOS, public privacy law) → ArchiMate concepts (meaning only) → SDEM-defined. Not used: TOGAF and the ArchiMate text (login), paid standards, vendor schemas, your employer's model. Confidence: **high** = a public standard defines it and it was checked; **medium** = built on a standard concept as SDEM chose; **low** = SDEM-defined.

## Decisions for you

1. **The three SDEM-defined attributes** (`disposition`, `system_of_record`, `retention_period`). *Recommended: keep all three* — rationalisation, golden source and retention are among the most-asked questions and no open standard covers them.
2. **`vendor`**. *Recommended: keep the name and re-source it to CycloneDX `supplier` (high).*
3. **Application criticality**. *Recommended: derive it (DV-A3-01) and store RTO/RPO instead*, consistent with the A2 decision.
4. **Required attributes**. *Recommended: none required* — exports from portfolio tools vary; the completeness warnings report gaps without rejecting data.
