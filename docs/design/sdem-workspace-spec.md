# Workspace specification

> **Status: built (v0.9.10)** — how a workspace is started, filled, planned from and how its BIAN layer is chosen. Owner's decisions, 2026-10-30: one name, *workspace*; every workspace starts with the BIAN layer; architects narrow it per workspace. User view: [README — the commands in order](../../README.md#2--tools), the [onboarding workflow](../sdem-onboarding-workflow.md), [planning with AID](../sdem-planning-with-aid.md).

| Id | Requirement | Verified by |
|---|---|---|
| WS-01 | `sdem new --workspace DIR --person P` starts a workspace: `a1-business.json`, `a3-application.json`, `a4-technology.json` empty; `a2-service-domain.json` your organisation's shared BIAN layer (`bian/a2-service-domain.json`, or `--bian FILE`), otherwise every service domain of the base BIAN with the accepted inferences (as `sdem bian import --base --all`); `--no-bian` starts without one; `mappings.json` empty. The whole workspace is checked before anything is written; a folder that exists and is not empty is refused; P is a person (CTL-21). | tests |
| WS-02 | `workspace.json` records who started it and when, and its BIAN layer: source, release, selection (`all`, `custom`, `none`), number of service domains and, when custom, the domains chosen. | tests |
| WS-03 | `sdem load` loads only into a workspace started with `sdem new`; otherwise it refuses and gives the `sdem new` command. `--person` records who decided which suggestions became architecture data. | tests |
| WS-04 | `sdem bian custom --workspace DIR (--only …\|--from FILE\|--all) --person P` narrows (or restores) one workspace's BIAN layer: built from the base (or `--base FILE`, or a folder), with `--patterns` and the accepted inferences; replaced through the BIAN update (BU-*), so it is checked, recorded in `bian-updates/` and refuses to remove a domain an approved connection uses; `workspace.json` records the selection. `sdem bian update --root` keeps a workspace with its own selection, reporting what the shared layer has that it does not. | tests |
| WS-05 | `sdem aid --workspace DIR --person P` fills the workspace's gaps in its own layer files, every inferred record marked (AID-W01…W07); `sdem aid confirm|reject` decide on them. File-based planning (`sdem aid project --workspace DIR`, into `DIR/plans/`, kept apart) still works. | tests |
| WS-06 | The option is `--workspace`; `sdem` still accepts the old `--estate`. Dashboards say *workspace*; `sdem home` writes `<out>/workspaces/<name>.html`. | tests |
