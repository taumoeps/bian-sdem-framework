## 0.7.0 — renamed SDEM, the Service Domain Enterprise Metamodel

- **Name.** SDMM → **SDEM (Service Domain Enterprise Metamodel)**, positioned as a model-driven enterprise architecture metamodel. Principles, A1–A4 levels, behaviour and data are unchanged.
- **Terms.** Architecture Metamodel (entity types, within-level rows, and the nine cross-level relationship types — now called the *relationship type catalogue*); Architecture Relationship Rules Model (plan rows and join keys); Architecture Relationship Inference Engine; Architecture Relationship Registry (was mapping set); local and federated architecture knowledge graphs. One ordered terminology module, `sdem/terms.py`, is applied to every generated document and diagram.
- **Package and commands.** `sdmm` → `sdem`; `sdmm/engine.py` → `sdem/inference.py`, `MappingEngine` → `RelationshipInferenceEngine`; commands `sdem-*` (`sdmm-engine` → `sdem-infer`), plus `sdem-diagram`. **Deprecated, kept for v0.7:** the `sdmm` package (warning shim), the `sdmm-*` commands, the `MappingEngine` name, `schema/mapping.schema.json`.
- **Files.** `schema/mapping.schema.json` → `schema/relationship-registry.schema.json`; `metamodel/new-mappings.json` → `relationship-rules.json`; diagrams `new-mappings.puml` → `relationship-rules.puml`, `merged-mappings.puml` → `merged-relationships.puml`; docs `mapping-model-design.md` → `sdem-overview.md` (rewritten), `mapping-model-spec.md` → `relationship-rules-spec.md`, `mapping-model-diagram.puml` → `architecture-model-diagram.puml`, `SDMM_v0.4_Entity_Metamodel_Specification.md` → `architecture-metamodel-spec.md`, `04-governance-and-impact.md` → `architecture-governance-spec.md`, `BIAN_SDMM_Design_Specification.md` → `BIAN_SDEM_Design_Specification.md`.
- **New.** `docs/relationship-registry-spec.md`, generated from the registry schema, the lifecycle and the type catalogue.
- **Model definitions.** Enum values `sdmm_extension`, `sdmm_definition`, `sdmm_reading`, field `sdmm_rule` and authority `sdmm` → `sdem_*` / `sdem`; the old values are still accepted.
- **Packaging.** `schema/` and `metamodel/` are bundled in the installed package (`sdem/data/`, located by `sdem/paths.py`), so `pip install .` works from any directory; previously `sdmm-graph` and `sdmm-engine` failed outside a checkout.
- **Deprecation schedule.** The compatibility layer (`sdmm` package, `sdmm-*` commands, `MappingEngine`, `schema/mapping.schema.json`, `sdmm_*` enum values) is removed in **v0.8.0**.
- **Not renamed:** registry record fields (`mappings`, `mapping_id`, `previous_mapping_id`) and catalogue fields (`mapping_type_id`, `registry_version`) — they sit inside immutable approved records; historical test logs and results; the GitHub repository name.

## 0.3.1

Level naming: the four design models are now the **Service Domain Architecture Design Model (SDADM)** — A1 Business Architecture, A2 Service Domain Architecture, A3 Application Architecture, A4 Technology Architecture. The `L0.`–`L3.` prefixes were an institution's own numbering, not a generic one.

- Entity types are prefixed `A1.`–`A4.`; the registry declares an ordered `levels` list, `bian_level`, and `type_aliases` mapping `L0.`–`L3.` to `A1.`–`A4.`.
- Older documents validate unchanged through the aliases; `sdmm-diff` treats an aliased prefix rename as no change, so approved records can be migrated without violating immutability.
- Registry version 0.3.0 (documents pinning `registry_version` bump the pin; that field is outside the frozen record).
- Adjacency and the BIAN-level `canonical_id` rule are driven by the registry's level list rather than a hard-coded digit.
- Docs renamed: `docs/01-a1-a2-mapping.md`, `02-a2-a3-mapping.md`, `03-a3-a4-mapping.md`.

## 0.3.0

- New `sdmm-trace` command: walk approved mappings downstream (what an entity depends on) or upstream (what depends on it), as a tree or JSON with every hop carrying its `mapping_id`. Superseded and proposed records are excluded unless `--status` includes them. Pure Python, no dependencies.
- Docs: v0.4 entity metamodel specification and roadmap track.

## 0.2.1

Validator hardening, in response to external review.

- `approved`, `rejected` and `superseded` records now require `approved_at` as well as `reviewer_id`.
- Mappings whose type has `bian_*` authority must carry `canonical_id` on their L1 endpoint. An unanchored BIAN-guided mapping no longer passes.
- Evidence may be cited as `kind:reference`; when it is, every kind in the registry's `required_evidence` must be present. Untyped evidence warns (`--strict` makes it an error).
- `EntityResolver` protocol and `CatalogueEntityResolver` (file-backed) let CI confirm every endpoint exists in a level model (`--catalogue`).
- New `sdmm-diff` command: lifecycle transitions and immutability of reviewed records, against a file or a git revision. Wired into CI against `HEAD~1`.
- Examples use typed evidence; `card-fraud-alerts` ships an `entities.json` catalogue.
- Docs: permitted transitions, immutability, evidence typing, authoritative vs derived relationships; roadmap reordered (graph before AI).
